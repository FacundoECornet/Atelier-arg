<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser → FormSpree API | Form data (including _gotcha) sent via HTTPS POST. FormSpree server-side checks _gotcha value. |
| Bot → Form (DOM) | Hidden _gotcha field is bait — bots auto-fill it, real users don't interact with it. |
| Password Manager → Form | autoComplete="off" prevents legitimate password managers from autofilling _gotcha (pitfall documented in RESEARCH.md line 641-648). |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-13 | Denial of Service | Contacto.jsx / Modal.jsx | mitigate | FormSpree _gotcha honeypot — automated spam bots that fill the hidden field are silently dropped by FormSpree server-side. Genuine users submit `_gotcha: ""` — accepted. |
| T-02-14 | Spoofing | Password manager autofill of _gotcha | mitigate | `autoComplete="off"` on _gotcha input prevents browser autofill. `style={{ display: 'none' }}` more aggressively hides from password managers than `type="hidden"`. If legitimate submissions are blocked, monitor FormSpree dashboard — mitigation is to remove the field (no harm done, it's honeypot-only). |
| T-02-15 | Information Disclosure | _gotcha field in DOM | accept | Field is in DOM and visible in page source. No secret information — it's a honeypot, its existence is not sensitive. |
| T-02-16 | Tampering | Client-side _gotcha bypass | accept | Bot can inspect DOM and skip _gotcha. Advanced targeted bots can bypass any client-side honeypot. FormSpree's honeypot blocks basic/naive bots — sufficient for a real estate site's threat model. Advanced spam would require CAPTCHA (paid FormSpree plan, out of scope per STATE.md). |
</threat_model>
